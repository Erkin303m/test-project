# Telegram Chat — прототип чата на GREEN-API

Клиентское React-приложение для отправки и получения **текстовых** сообщений
в **Telegram** через HTTP API **GREEN-API**.

По условию задания в качестве мессенджера можно использовать MAX, WhatsApp
или Telegram. Реализован вариант на Telegram; внешний вид повторяет
веб-версию мессенджера.

Приложение полностью работает в браузере: GREEN-API отдаёт входящие
уведомления прямо клиенту (CORS разрешён), поэтому бэкенд не требуется.

---

## Возможности

- Вход по учётным данным GREEN-API (`idInstance` + `apiTokenInstance`).
- Создание чата по номеру телефона **или** по `@username`.
- Отправка текстовых сообщений с оптимистичным обновлением интерфейса.
- Приём входящих сообщений в реальном времени (long-poll).
- Статусы доставки и прочтения, разбивка переписки по датам и группировка
  сообщений в пузыри.
- Сохранение учётных данных и истории переписки в `localStorage`.

## Стек

React 19 · TypeScript · Vite 8 · oxlint. Без UI-библиотек и стейт-менеджеров —
только CSS с токенами темы Telegram.

### Переменные окружения

Не требуются: `idInstance` и `apiTokenInstance` вводятся в интерфейсе и
хранятся только в вашем браузере.

## Как пользоваться

1. Зарегистрируйтесь в [личном кабинете GREEN-API](https://console.green-api.com/instanceList)
   и создайте инстанс. Один инстанс = один аккаунт Telegram.
2. **Авторизуйте инстанс** одним из двух способов:
   - **QR-код (рекомендуется).** В приложении Telegram: `☰` → `⚙ Настройки` →
     `🖳 Устройства` → `Подключить устройство`. Затем в кабинете GREEN-API
     нажмите `Получить QR` и отсканируйте его. QR обновляется каждые ~5 секунд.
   - **Код из приложения.** `StartAuthorization` → код приходит в служебный
     чат Telegram или по SMS (действует 5 минут). При двухфакторной
     аутентификации дополнительно нужен пароль. Telegram ограничивает частоту
     таких попыток, поэтому документация рекомендует QR.
3. Скопируйте из кабинета `idInstance`, `apiTokenInstance` и **`apiUrl`**.
4. В приложении введите `idInstance` и `apiTokenInstance`, нажмите
   «Подключиться». Если в кабинете задан персональный `apiUrl`, раскройте
   поле «Указать адрес API вручную» и вставьте его.
5. Нажмите «+» в боковой панели, укажите номер телефона или `@username`
   получателя и создайте чат.
6. Напишите сообщение. Получатель ответит в Telegram — ответ появится
   в чате автоматически.

## Используемые методы API

Документация: <https://green-api.com/telegram/docs/> (обратите внимание:
раздел Telegram находится по своему пути, а не `/v3/docs/`).

| Метод | Назначение |
| --- | --- |
| `GET getSettings` | проверка учётных данных, чтение `webhookUrl` |
| `GET getStateInstance` | проверка авторизации инстанса |
| `POST checkAccount` | телефон или `@username` → `chatId` |
| `POST sendMessage` | отправка текста |
| `GET receiveNotification` | приём уведомления (long-poll) |
| `DELETE deleteNotification` | подтверждение обработки уведомления |

Путь запросов такой же, как у других мессенджеров GREEN-API:
`{apiUrl}/waInstance{idInstance}/{method}/{apiTokenInstance}`.

### Как устроен приём сообщений

Приём реализован циклом в `src/hooks/useNotifications.ts`:

1. `GET receiveNotification?receiveTimeout=25` — long-poll, сервер держит
   соединение до 25 секунд.
2. Полученное уведомление разбирается в `src/api/notifications.ts`:
   - `incomingMessageReceived` → новое сообщение в чат;
   - `outgoingMessageStatus` → обновление галочек у уже отправленного
     сообщения (`delivered`, `read`, `failed`, `noAccount`);
   - остальные типы (`stateInstanceChanged`, `quotaExceeded`, …)
     игнорируются — по условию задачи нужны только тексты.
3. `DELETE deleteNotification/{receiptId}` — подтверждение. Без него
   уведомление вернётся в очередь и будет приходить повторно.

При ошибках сети используется экспоненциальная задержка до 30 секунд.

## Особенности Telegram API

- **Адресация чатов.** В личных чатах `chatId` — голое число
  (`10000000`), в группах — отрицательное (`-10000000000000`). Префикс
  `@c.us` в API сохранился только для отправки по номеру телефона и
  использовать его для переписки не нужно: он ломает сопоставление
  входящих сообщений. Поэтому телефон или `@username` один раз
  резолвятся в `chatId` методом `checkAccount`, а дальше отправка идёт
  по `chatId`.
- **`checkAccount` строго троттлится.** 10 req/s у GREEN-API плюс
  собственные ограничения Telegram на аккаунт: при превышении приходит
  HTTP **469** (`Rate limited by messenger`), и Telegram не сообщает срок
  ожидания — повторять придётся через несколько часов. На бесплатном
  тарифе «Разработчик» доступно всего **100 проверок наличия** аккаунта,
  поэтому клиент не опрашивает `checkAccount` без явного действия
  пользователя. Отдельные сообщения об ошибке в `GreenApiError`
  различают 429 (лимит GREEN-API) и 469 (лимит Telegram).
- **`webhookUrl` должен быть пустым.** Если в настройках инстанса указан
  `webhookUrl`, приём по HTTP API отключается
  (`400 Message cannot be received because custom webhook url is set`).
  Приложение проверяет это при входе и показывает предупреждение.
- **Поля статуса лежат на верхнем уровне.** В `outgoingMessageStatus`
  `chatId` и `status` не вложены в `senderData`, в отличие от входящего
  сообщения. Парсер учитывает оба варианта.
- **Гонка при отправке.** Telegram подтверждает доставку быстрее, чем
  приходит HTTP-ответ `sendMessage`, поэтому статус может прийти на ещё
  не подставленный временный `id`. Редьюсер применяет такой статус к
  последней неотправленной записи чата и не откатывает его при замене
  временного `id` на настоящий.
- **Длина сообщения** — до 4096 символов.
- **Лимиты частоты запросов** (<https://green-api.com/telegram/docs/api/ratelimiter/>):
  `sendMessage` — 50/с, `receiveNotification` и `deleteNotification` —
  100/с, `checkAccount` — 10/с, `getSettings`, `getStateInstance`,
  `getChats`, `getContacts` — по 1/с. Клиент троттлит медленные методы
  локально, long-poll ждёт 25 секунд, поэтому упирается в лимит только
  при непрерывном потоке уведомлений.

## Дизайн

Палитра взята из стандартной светлой темы Telegram Desktop — файл
`ui/colors.palette` в исходниках tdesktop (`windowBgActive` `#40a7e3`,
`msgInBg` `#ffffff`, `msgOutBg` `#effdde`, `msgInDateFg` `#a0acb6`,
`msgOutDateFg` `#6db566`). Разделитель дат — полупрозрачная плашка
`msgServiceBg`. Галочки доставки зелёные, прочтения — синие, как в
Telegram.

## Структура проекта

```
src/
  api/
    types.ts          типы запросов, ответов и уведомлений
    greenApi.ts       HTTP-клиент GREEN-API с троттлингом и обработкой ошибок
    notifications.ts  разбор входящих уведомлений в модель приложения
  components/
    LoginScreen.tsx   вход по учётным данным инстанса
    Sidebar.tsx       список чатов
    NewChatDialog.tsx создание чата по телефону или @username
    MessageList.tsx   лента сообщений, группировка, разделители дат
    MessageBubble.tsx пузырь сообщения
    StatusTicks.tsx   галочки статуса
    Composer.tsx      поле ввода
    Avatar.tsx        аватар чата
  hooks/
    useNotifications.ts  цикл ReceiveNotification / DeleteNotification
  lib/
    reducer.ts        операции над состоянием переписки
    storage.ts        localStorage
    format.ts         телефоны и время
    recipient.ts      разбор «телефон или @username»
    avatar.ts         цвета аватаров
```
